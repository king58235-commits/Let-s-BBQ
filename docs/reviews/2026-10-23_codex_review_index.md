## 審查的盲點與誤差
- Codex 指出「背景描述每串 3–6 個食材，但程式與 README 是 2–4 個」：程式是對的，**錯的是我給它的任務描述**。這是這個流程的典型代價：審查品質受委託說明正確度影響，且它沒有因此亂報成程式缺陷。
- Codex 自述沒有在真實瀏覽器跑 12 項測試，也沒量測音訊記憶體；音訊節點洩漏、長時間遊玩仍是未驗證項目。
- 6 項全為「確定」，沒有誤報。樣本只有一次，不能據此推論它的準確率。
- 審查沒有涵蓋：繪圖（`draw*`）、素材載入、手機實機行為。

## 對流程的觀察
- 一次審查約 45 萬輸入 token（多數走快取），相對於一次生圖不算大，但是真實額度占比未量測。
- Codex 的發現多數需要「構造特定操作序列」才會出現（多指、補位瞬間、低影格率），這類問題我自己寫的測試沒有涵蓋；它的價值在於換一個視角讀同一份碼。
- 如果要用這個流程當慣例：委託說明要先由我對照程式核對，避免像這次把規格寫錯。
